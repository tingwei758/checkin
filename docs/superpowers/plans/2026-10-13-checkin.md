# Check-in Runner Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single-container Python service that performs the daily 签到 check-in on ~10 private-tracker sites behind Cloudflare and shows the results on one status page.

**Architecture:** Pure functions for the parts worth testing (config loading, response classification, scheduling arithmetic, row building), thin shells for the parts that touch the world (curl_cffi fetch, SQLite, APScheduler, Flask). One process runs the scheduler and the web app together. History lives in SQLite as one row per attempt; the dots, streak and attempt counts are queries, not maintained counters.

**Tech Stack:** Python (source 3.9-compatible, image 3.12), curl_cffi, APScheduler, Flask, Jinja2, PyYAML, SQLite (stdlib), pytest.

**Spec:** `docs/superpowers/specs/2026-10-13-checkin-design.md`

## Global Constraints

- Project root: `checkin/` (all paths in this plan are relative to it). Not yet a git repo — Task 1 initialises it.
- Schedule: `03:20` Asia/Shanghai, per-site jitter window `0–20` minutes, drawn per site per day.
- Retries: `+15 minutes` then `+1 hour`; three attempts maximum per site per day.
- No catch-up for missed days. A missed 03:20 is simply skipped.
- Retention: `90` days of attempt history. Status page shows `7` days.
- Outcomes are exactly three: `success`, `already`, `failure`.
- "Today" means the Asia/Shanghai calendar day everywhere.
- HTTP goes through curl_cffi with Chrome impersonation. No browser automation, no proxy support, no form logins, no push notifications.
- Status page is LAN-only, no authentication.
- Source must import and run on Python 3.9: `from __future__ import annotations` in every module, no `match`, no PEP-604 unions at runtime, no `zoneinfo` fallbacks beyond stdlib.
- Target size roughly 500 lines of source. No plugin system, no DB migrations, no frontend build step.
- Tests run as `.venv/bin/python -m pytest`; the venv is created from system `python3` (3.9) in Task 1.

## Review Focus

- A configured site with no entry in `cookies.yaml` must show "no cookie configured" on its row and never fire a request — pinned in Task 2.
- A network exception (timeout, DNS failure, TLS error) must be recorded as a `failure` with its reason, not propagate and kill the scheduler job — pinned in Task 4.
- A response body that is not valid UTF-8 must still classify and store, with the excerpt truncated — pinned in Task 4.
- `next_run_time` must be computed in Asia/Shanghai regardless of host clock, since the Mac is UTC+8-unaware and the image sets TZ separately — pinned in Task 5.
- Malformed YAML in either file must fail with a message naming the file and the problem, not a bare traceback — pinned in Task 2.

### Task 3: Attempt store

**Files:**
- Create: `checkin/store.py`
- Test: `tests/test_store.py`

**Interfaces:**
- Consumes: nothing.
- Produces:
  - `SUCCESS = "success"`, `ALREADY = "already"`, `FAILURE = "failure"` module constants
  - `@dataclass(frozen=True) Attempt` with `site: str`, `outcome: str`, `message: Optional[str]`, `streak: Optional[int]`, `detail: Optional[str]`, `at: datetime`
  - `class Store` with `__init__(self, db_path: Path)` (creates the schema if absent), and methods:
    - `record(self, attempt: Attempt) -> None`
    - `attempts_on(self, site: str, day: date) -> List[Attempt]` — ascending by `at`
    - `latest(self, site: str) -> Optional[Attempt]`
    - `day_outcomes(self, site: str, days: Sequence[date]) -> Dict[date, str]` — best outcome per day, `success` > `already` > `failure`; days with no attempt are absent from the dict
    - `prune(self, keep_days: int, today: date) -> int` — deletes older rows, returns the count
- Every method opens its own short-lived `sqlite3` connection, because the Flask thread and the scheduler thread both write. Timestamps are stored as ISO strings in Asia/Shanghai with offset, and `day` filtering uses the date prefix of that string.

### Task 4: Fetch and classify

**Files:**
- Create: `checkin/checker.py`
- Test: `tests/test_checker.py`

**Interfaces:**
- Consumes: `Site` from `checkin.config`; `SUCCESS`/`ALREADY`/`FAILURE` from `checkin.store`.
- Produces:
  - `@dataclass(frozen=True) CheckResult` with `outcome: str`, `message: Optional[str]`, `streak: Optional[int]`, `detail: Optional[str]`
  - `EXCERPT_CHARS = 200`
  - `classify(site: Site, status_code: int, body: str) -> CheckResult`
  - `fetch(site: Site, timeout: float = 30.0) -> Tuple[int, str]` — the curl_cffi call
  - `check(site: Site, fetch_fn: Callable[[Site], Tuple[int, str]] = None) -> CheckResult` — `fetch_fn` defaults to `fetch`; catches every exception from it and returns a `FAILURE` result whose `detail` is `"{ExceptionClass}: {message}"` truncated to `EXCERPT_CHARS`
- On success or already, `message` is the whole span matched by that site's pattern, whitespace-collapsed. `streak` is group 1 of the streak pattern as an int, or `None` if the pattern is absent or does not match.
- Classification order: no cookie → Cloudflare → success → already → unmatched.

### Task 5: Scheduling arithmetic and the runner

**Files:**
- Create: `checkin/runner.py`, `checkin/schedule.py`
- Test: `tests/test_schedule.py`, `tests/test_runner.py`

**Interfaces:**
- Consumes: `Config`, `Site` from `checkin.config`; `Store`, `Attempt`, outcome constants from `checkin.store`; `check`, `CheckResult` from `checkin.checker`.
- Produces in `checkin/schedule.py` (pure, no APScheduler import):
  - `RETRY_DELAYS = (timedelta(minutes=15), timedelta(hours=1))`
  - `next_run_time(now: datetime, run_at: time, tz: tzinfo) -> datetime` — the next occurrence strictly after `now`, in `tz`
  - `jitter_seconds(site_name: str, day: date, window_minutes: int) -> int` — deterministic for a given (site, day), uniform in `[0, window_minutes * 60)`
  - `retry_delay(attempt_number: int) -> Optional[timedelta]` — 1 → 15 min, 2 → 1 h, 3+ → `None`
  - `should_attempt(attempts_today: Sequence[Attempt]) -> bool` — `False` once any attempt is `success` or `already`, or once three attempts exist
- Produces in `checkin/runner.py`:
  - `class Runner` with `__init__(self, config_path: Path, cookies_path: Path, store: Store, scheduler=None, check_fn=check)`
    - `config(self) -> Config` — re-reads both files from disk on every call, so an edited cookie takes effect with no restart
    - `run_site(self, site: Site, *, force: bool = False) -> CheckResult` — records the attempt; when `force` is `False`, skips and returns the recorded result if `should_attempt` says no; schedules the retry from `retry_delay` when the outcome is `FAILURE` and a delay exists
    - `run_all(self) -> Dict[str, CheckResult]` — sequential over enabled sites
    - `start(self) -> None` — registers the daily cron job at `run_at` in the configured timezone, plus a daily prune; a missed fire is dropped (`misfire_grace_time` small, `coalesce=True`), never caught up
    - `next_run(self) -> datetime` — for the page's countdown
  - The daily job schedules one one-off job per enabled site at `now + jitter_seconds(...)`.
